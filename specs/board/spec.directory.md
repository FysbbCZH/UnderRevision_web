# Board 目录管理前端设计

## 目标

- 在用户进入 Board 后，以目录树管理该 Board 的非根目录。
- 支持目录的创建、查询、重命名、移动和递归删除，并与后端 Directory 接口及领域约束保持一致。
- 对请求状态、结果未知和破坏性操作提供明确反馈，不把未确认的结果显示为成功。
- 本 Spec 只设计目录操作；Item 与文件交互由 `item/spec.md` 负责。

## 配置项

- 本 Spec 不新增配置项；目录请求沿用 Board 主规范定义的 `{API_BASE_URL}`。

## 详细设计

### 功能范围

用户必须先进入一个已存在的 Board，才能管理该 Board 的目录。本阶段提供：

1. 查询并展示 Board 的完整非根目录树。
2. 在 Board 顶层或一个非根目录下创建目录。
3. 查询并选中一个非根目录。
4. 修改非根目录名称。
5. 将非根目录移动到 Board 顶层或另一个非根目录下。
6. 递归删除非根目录及其全部子目录。

目录操作是同步元数据操作，不展示为异步任务。每项操作仍必须展示请求状态与错误；请求超时、断网或连接中断时，不得把未知结果显示为成功或失败。

### 页面结构

#### Board 详情中的目录工作区

目录管理位于 Board 详情页，并使用当前路由中的 `board_id` 作为唯一 Board 上下文。目录工作区应包含：

- “目录”标题、目录数量、刷新状态和“新建顶层目录”入口。
- 可展开和折叠的目录树；后端根目录不显示，直接位于根目录下的目录作为树的第一层。
- 当前选中目录的名称和操作区，包括“新建子目录”“重命名”“移动”“删除”。
- 首次加载、刷新中、空树、加载失败和 Board 不存在状态。
- 加载失败后的手动重试入口。

目录树为空时，应说明尚未创建目录并提供创建顶层目录入口，不把空树显示为错误。没有选中目录时，操作区说明需要先选择目录，不默认选中并操作第一项。

#### 目录树交互

- 每个节点以目录名称为主信息；必要时可以弱化显示子目录数量，不展示 `creator_id`、`board_id` 或内部根目录信息。
- 有子目录的节点提供明确的展开与折叠控件；展开状态只影响当前页面展示，不改变服务端数据。
- 选择目录和展开目录必须是两个可区分的操作，不能因展开而触发变更。
- 服务端返回的同层顺序即为展示顺序，前端不得自行拖拽排序或重新排序。
- 目录树刷新后，若原选中目录仍存在，则保留选中；若已不存在，则清除选择并说明数据已经变化。

本阶段不提供拖拽移动，避免拖拽、选中和展开在桌面或窄屏设备上产生歧义。移动目录使用独立界面显式选择目标父目录。

#### 新建目录

新建界面可以使用对话框或抽屉，但必须包含：

- 目录名称输入框及可识别标签。
- 只读的目标位置说明：Board 顶层或选中的父目录。
- 创建、取消操作和创建进行中状态。
- 输入错误或请求失败后的可读错误信息。

从工具栏进入时，在 Board 顶层创建目录；从选中目录的操作区进入时，在该目录下创建子目录。创建成功后关闭界面、刷新目录树并选中新目录。创建失败后保留名称和目标位置，方便修改或再次提交。

#### 重命名目录

重命名界面显示当前名称，并包含新名称输入框、保存和取消操作。保存进行中不得重复提交。只有收到后端成功响应后，目录树和选中目录信息才能更新；失败时保留输入值和原名称。

#### 移动目录

移动界面必须显示当前目录和当前父级，并提供以下目标：

- Board 顶层。
- 当前 Board 中除待移动目录及其全部子孙目录外的其他非根目录。

后端根目录不得作为一个真实目录选项展示，“Board 顶层”在请求中使用 `parent_id: null`。当前父级可以展示但不作为需要提交的变化；无有效目标时应说明原因，不提供无意义提交。

移动进行中不得重复提交。只有收到后端成功响应后，才改变目录在树中的位置；失败时保留原位置和用户选择。前端对自身和子孙目标的排除只用于避免无效操作，服务端仍是目录归属、防环和深度限制的最终判断者。

#### 删除目录

删除是不可恢复操作，必须在独立确认界面中展示目标目录名称，并明确说明该目录、全部子目录及其中的 Item 都会被递归删除。用户必须显式确认后才发送请求；普通 Enter 不得直接触发确认。

删除成功后刷新目录树并清除被删除子树中的当前选择；若页面同时提供 Item 管理，还必须刷新 Item 树，不得保留已随目录删除的 Item。删除失败时保留原树、Item 树和当前选择，不得提前移除节点或部分子树。

### 视觉与布局

#### 整体布局

- 目录工作区延续 Board 主规范的研究工作台风格和现有颜色、间距、状态及按钮语义。
- 常见桌面宽度下使用“目录树 + 当前目录操作区”的双栏布局；目录树是主区域，操作区是辅助区域。
- 较窄窗口下改为纵向布局，当前目录操作区位于目录树之后，不产生阻止操作的横向滚动。
- 目录层级通过缩进、连接关系或等价的低干扰方式表达，不只通过颜色区分。
- 长目录名称允许换行或安全截断并提供完整可访问名称，不能挤压掉展开、选择或操作入口。

#### 状态与反馈

- 首次加载可使用与现有 Board 页面一致的骨架或占位区域；刷新时保留已确认目录树并显示非阻塞刷新状态。
- 成功反馈应简短且说明已确认的操作；失败和结果未知反馈必须持续到用户关闭、修改输入或主动核对。
- 进行中状态可以使用加载指示，但必须同时提供文本，不得只显示动画。
- 名称冲突、防环和深度超限应使用可读业务提示，不只展示错误码。

### 页面状态与一致性

目录查询与变更沿用 Board 主规范的 `QueryStatus` 和 `MutationStatus`：

- 目录树查询与每个变更操作分别管理状态，避免一个操作的错误覆盖另一个操作。
- 同一创建、重命名、移动或删除请求处于 `submitting` 时，必须阻止对应操作重复提交。
- 不使用乐观更新；只有契约校验通过的成功响应才更新已确认目录树。
- GET 请求失败可以由用户手动重试；前端不得无期限轮询。
- 变更请求不得自动重试。浏览器无法确认结果时进入 `result_unknown`，保留最后一次已确认目录树，并引导用户重新查询。
- 创建、重命名或移动结果未知后，重新查询整棵目录树，以服务端现状恢复页面。
- 删除结果未知后，先重新查询目标目录：若返回 `404 DIRECTORY_NOT_FOUND`，则把删除视为已确认并刷新目录树；若目录仍存在，则展示实际状态并允许用户重新决定；核对请求失败时继续保持结果未知。
- 切换 Board 或离开页面时，应取消不再需要的查询，旧 Board 的响应不得覆盖当前 Board。

### 输入规则

- 目录名称提交前去除首尾空白。
- 名称长度必须为 1 至 200 个 Unicode 字符；不满足时不得发送请求，并在输入框附近提示。
- 同一父目录下名称不可重复，不同父目录可以同名；前端可以基于当前已确认目录树提前提示，但以后端响应为准。
- 目录名称区分大小写，并作为逻辑名称处理；前端不得把 `/` 或 `\\` 解释为浏览器文件系统路径。
- `board_id` 必须来自当前 Board 路由，`dir_id` 与目标 `parent_id` 必须来自后端已经确认的目录响应；不提供手工输入 ID 的入口。
- 前端不发送或修改 `creator_id`、`board_id` 及其他未声明字段。

### 接口数据契约

#### 目录响应

```typescript
interface DirectoryResponse {
  dir_id: string;
  dir_name: string;
  parent_id: string | null;
  board_id: string;
  creator_id: string;
}

interface DirectoryTreeNode extends DirectoryResponse {
  children: DirectoryTreeNode[];
}

interface DirectoryTreeResponse {
  directories: DirectoryTreeNode[];
}
```

`directories` 只包含用户可操作的非根目录。直接位于 Board 根目录下的目录返回 `parent_id: null`；响应中不得出现后端根目录节点或根目录 ID。

#### 请求体

```typescript
interface CreateDirectoryRequest {
  dir_name: string;
  parent_id: string | null;
}

interface UpdateDirectoryRequest {
  dir_name?: string;
  parent_id?: string | null;
}
```

创建顶层目录时发送 `parent_id: null`。更新请求至少提供一个字段；重命名只发送 `dir_name`，移动只发送 `parent_id`，不把未修改字段作为推测值一并提交。

错误响应沿用 Board 主规范的 `ErrorResponse`。前端优先展示后端返回的可读 `message`；响应不满足契约、连接失败或无法解析时，展示统一通用错误，不泄漏原始响应或内部信息。

### 接口交互

统一目录前缀为 `{API_BASE_URL}/api/v1/boards/{board_id}/directories`。

#### 查询目录树

- 向目录前缀发送 `GET` 请求。
- 只有收到 `200 OK` 且响应满足 `DirectoryTreeResponse` 时，才更新目录树。
- `directories` 为空时进入空树状态。
- `404 Not Found` 或错误码 `BOARD_NOT_FOUND` 时展示 Board 不存在状态，并允许返回 Board 主界面。

#### 查询单个目录

- 向 `{API_BASE_URL}/api/v1/boards/{board_id}/directories/{dir_id}` 发送 `GET` 请求。
- 只有收到 `200 OK` 且响应满足 `DirectoryResponse` 时，才把结果用于状态核对。
- `404 Not Found` 或错误码 `DIRECTORY_NOT_FOUND` 表示目标目录不存在或不可操作，不保留过期详情冒充有效数据。

#### 创建目录

- 向目录前缀发送 `POST` 请求，请求体为 `CreateDirectoryRequest`。
- 只有收到 `201 Created` 且响应满足 `DirectoryResponse` 时，才显示创建成功。

#### 重命名或移动目录

- 向 `{API_BASE_URL}/api/v1/boards/{board_id}/directories/{dir_id}` 发送 `PATCH` 请求，请求体为 `UpdateDirectoryRequest`。
- 只有收到 `200 OK` 且响应满足 `DirectoryResponse` 时，才更新已确认状态。

#### 删除目录

- 向 `{API_BASE_URL}/api/v1/boards/{board_id}/directories/{dir_id}` 发送 `DELETE` 请求。
- 只有收到 `204 No Content` 时，才把目标目录及其子目录从已确认状态中移除。

#### 业务错误

- `404 BOARD_NOT_FOUND`：当前 Board 已不存在或不可见，停止目录操作并提供返回入口。
- `404 DIRECTORY_NOT_FOUND`：目标目录已不存在、属于其他 Board 或不可操作，提示刷新目录树。
- `409 DIRECTORY_NAME_CONFLICT`：提示同一位置已存在同名目录，保留输入或移动选择。
- `409 DIRECTORY_CYCLE`：提示不能把目录移动到自身或其子目录，保留原树。
- `409 DIRECTORY_DEPTH_EXCEEDED`：提示目标位置会超过最大目录深度，保留原树并允许重新选择。
- `422 INVALID_DIRECTORY_REQUEST`：提示名称或请求内容不合法，保留可修改输入。
- 未识别的错误码按通用失败处理，不向用户显示内部堆栈、HTML、SQL 或本机路径。

### 用户身份与资源边界

- 本阶段不新增登录、权限或用户切换界面；沿用 Board 主规范中的 MVP 用户约束。
- 所有目录请求都必须携带当前路由的 `board_id`，不得仅凭 `dir_id` 跨 Board 查询或变更。
- 返回数据中的 `board_id` 必须等于当前路由 `board_id`；不一致时视为前后端契约错误，不展示或写入本地状态。
- `creator_id` 只用于响应契约校验，不在目录工作区展示或编辑。

### 可用性与浏览器行为

- Chrome 必须能够完成创建多层目录、展开树、选择目录、重命名、移动和递归删除流程；Safari、Firefox 为可选支持。
- 树节点、展开控件、表单和操作按钮必须具有可识别名称，并可通过键盘到达。
- 当前选中、展开、危险和错误状态不得只通过颜色表达。
- 对话框或抽屉必须支持清晰的关闭与焦点返回；提交进行中不得关闭造成重复判断。
- 用户提供的目录名称和后端错误消息均作为文本展示，不得作为 HTML 注入页面。

## 约束

### 前后端契约一致性

- 只能调用本 Spec 定义的五个 Directory 接口，不得假定存在搜索、分页、批量操作、排序写入、软删除、回收站、恢复或复制接口。
- 前端发送和接收的字段名、状态码及错误结构必须与本 Spec 一致，不得把后端内部根目录或数据库列名暴露为前端合同。
- 服务端是 Board 归属、目录存在性、同级名称唯一、防环和最大深度的最终判断者；前端检查不能替代服务端响应。

### 数据一致性

- 目录变更不得并发重复提交、自动重试或在成功响应前进行乐观更新。
- 浏览器无法确认请求结果时必须标识结果未知，并通过查询服务端状态核对，不得通过猜测更新目录树。
- 刷新失败时保留最后一次已确认目录树，并明确提示页面可能不是最新状态。
- 响应状态码成功但数据结构、Board 归属或树结构不符合契约时，视为契约错误，不展示部分树。

### 根目录透明

- 前端不得展示、缓存、请求、编辑、移动或删除 Board 根目录及其 ID。
- “Board 顶层”只是用户界面概念，使用 `parent_id: null` 与后端交互，不伪造根目录节点。

### 范围限制

- 目录模块不实现 Item 增删改查、文件上传下载或分类操作；这些能力由 `item/spec.md` 提供。
- 不实现知识、产物或 Agent 任务界面。
- 不展示目录中的 Item 数量、文件大小、文件类型或其他后端未提供的数据。
- 不实现拖拽移动、目录搜索、分页、批量创建、批量移动、批量删除、复制、软删除、回收站或恢复。
- 不把目录树持久化到浏览器缓存以替代服务端查询。
